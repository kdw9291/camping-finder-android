## 2. 설계 결정

### 2.1 ★ "모름" 을 화면에 드러낸다

이 앱이 다른 캠핑 앱과 갈리는 지점이다. 백엔드에서 849곳을 살린 설계가 화면에서 무너지면 의미가 없다.

| 화면 | 처리 |
|---|---|
| 목록 | `sbrsKnown == false` 면 빈칸이 아니라 **"시설 정보 없음"** |
| 상세 | **"정보가 없는 항목"** 절을 따로 두고 *"시설이 없다는 뜻이 아닙니다"* 명시 |
| 썸네일 | 이미지가 없으면 회색 네모가 아니라 **"사진 없음"** |
| 검색 | `includeUnknown=true` 가 기본값 |

썸네일도 같은 원칙이다. 회색 네모만 두면 **로딩 중인지 이미지가 없는 건지 구분되지 않아** 사용자가 오지 않을 이미지를 기다린다.

### 2.2 Paging 3 를 쓰지 않았다

서버가 단순 오프셋 페이지 API 이고 전체가 2,955건이다.
Paging 이 주는 이점(대용량 스트리밍, DB 캐시 연동)이 **이 규모에서는 실현되지 않는다.**

직접 구현하면 로딩·에러·끝 도달 상태가 한눈에 보이고, `endReached` 판정도 명시적이다.
필요해지면 그때 바꾼다. **쓰지 않은 이유를 적는 편이 쓴 것보다 낫다.**

### 2.3 계약 테스트 — 기기 없이 서버 응답을 검증한다

에뮬레이터를 띄우지 않고도 **서버가 주는 형태와 앱이 기대하는 형태가 어긋났는지** 확인한다.
픽스처는 지어낸 JSON 이 아니라 **운영 API 에서 실제로 받은 응답**이다.

- `sbrsKnown`·`unknownCategories` 가 응답에 **실제로 존재하는지**
  (기본값 `false` 로 조용히 채워지는 것과 구분해야 한다)
- `sbrsKnown=true` 인데 시설 목록이 비어 있지 않은지 (앞뒤가 맞는지)
- null 이 섞여도, 서버가 필드를 추가해도 견디는지

**서버가 응답을 바꾸면 여기서 먼저 깨진다.** 앱을 켜서 빈 화면을 보고 알아채는 것보다 낫다.

### 2.4 디버그 빌드도 운영 API 를 본다

백엔드가 이미 인터넷에 있으므로 앱 개발할 때마다 로컬 서버를 띄울 이유가 없다.
로컬 백엔드를 보려면 `app/build.gradle.kts` 의 `API_BASE_URL` 한 줄만 바꾼다.
(에뮬레이터에서 호스트 PC 는 `10.0.2.2` 다. `localhost` 는 에뮬레이터 자신이다.)

## 3. ★ 실패 기록

### 3.1 Coil 최신 버전을 쓸 수 없다 — Kotlin 메타데이터 충돌

```
e: kotlin-stdlib-2.4.0.jar!/META-INF/kotlin-stdlib.kotlin_module
   Module was compiled with an incompatible version of Kotlin.
   The binary version of its metadata is 2.4.0, expected version is 2.2.0.
```

**AGP 9 는 Kotlin 을 내장한다(2.2.10).** 최신 Coil 3.5.0 이 stdlib 2.4.0 을 끌어오면서
컴파일러가 읽을 수 없는 메타데이터가 들어왔다.

`dependencyInsight` 로 원인을 특정했다 — **Coil 만이 2.4.0 을 요구했고 나머지는 전부 2.3.21 이하였다.**

| Coil | stdlib 요구 |
|---|---|
| 3.5.0 | 2.4.0 ❌ |
| 3.4.0 | 2.3.10 (경계선) |
| **3.3.0** | **2.2.0 ✅** |

3.3.0 으로 고정했다. 경계선인 3.4.0 은 피했다.

> **교훈: AGP 9 를 쓰는 동안 라이브러리 최신 버전이 항상 쓸 수 있는 것은 아니다.**
> 새 의존성을 넣기 전에 stdlib 요구 버전을 먼저 본다.

### 3.2 `joinToString` 안에서는 `@Composable` 을 부를 수 없다

```
e: @Composable invocations can only happen from the context of a @Composable function
```

`map`, `forEach` 는 inline 이라 람다 본문이 호출부에 인라인되어 컴포저블 컨텍스트가 유지된다.
**`joinToString` 은 inline 이 아니다.** 먼저 `map` 으로 변환한 뒤 이어붙인다.

### 3.3 추가 로딩 실패가 화면에 표시되지 않았다

목록이 이미 있는 상태에서 다음 페이지 로딩이 실패하면 `errorMessage` 를 설정하긴 했는데,
**화면에는 목록이 비었을 때만 표시하도록 짜여 있었다.**

즉 스크롤하다 네트워크가 끊기면 **스크롤이 그냥 멈추고 아무 설명이 없었다.**
사용자는 목록이 끝난 건지 앱이 고장난 건지 알 수 없다. 스낵바로 알리도록 고쳤다.

> 실기기로 화면을 보지 않았으면 계속 몰랐을 결함이다.
