# M3 — 지도와 조합 필터

> 2026-08-11 · 네이버 지도 SDK 연동, 시설 조합 필터 UI
> 결과: 실기기(Galaxy S25)에서 타일·마커 정상, 필터 동작 확인

---

## 1. 인수 조건

- [x] 지도에 캠핑장 마커 표시, 탭하면 상세로 이동
- [x] "이 지역에서 검색" — 줌 레벨에 따른 반경
- [x] 시설 조합 필터 (AND), 업종 필터 (OR), 반려동물
- [x] **`includeUnknown` 을 사용자가 직접 켜고 끌 수 있다** ← 849곳이 사용자 손에 들어온다
- [x] 필터 항목을 앱에 하드코딩하지 않는다

---

## 2. 설계 결정

### 2.1 ★ 필터의 핵심은 "정보 없음 포함" 스위치다

시트 맨 위에 두고 **기본값을 켬**으로 했다. 설명도 함께 적었다.

> **시설 정보가 없는 곳도 포함**
> 끄면 정보가 확인된 곳만 나옵니다. **시설이 없는 곳을 빼는 것이 아닙니다.**

실측 차이:

| `sbrs=전기` | 결과 |
|---|---|
| 미상 포함 (기본) | **2,846** |
| 미상 제외 | **1,997** |

**849곳.** M0 에서 "빈 값은 없음이 아니라 모름" 이라고 판단한 것이
스키마(`campsite_facility_known`) → 쿼리 → API → 화면 스위치까지 한 줄로 이어졌다.

### 2.2 필터 항목은 서버에서 받는다

`/api/filters` 를 호출해 칩을 만든다. 앱에 박아두면
**공공데이터가 항목을 하나 늘릴 때마다 스토어 심사를 다시 받아야 한다.**

필터 목록 조회가 실패해도 검색은 막지 않는다. 필터만 비어 보인다.

### 2.3 "적용" 을 눌러야 검색이 나간다

칩을 누를 때마다 요청하면 조합을 고르는 동안 목록이 계속 흔들린다.
시트 안에서 초안(draft)을 편집하고 적용 시점에만 한 번 보낸다.

### 2.4 지도는 자동 재검색하지 않는다

카메라가 멈출 때마다 부르면 팬·줌 한 번에 요청이 수십 개 날아간다.
사용자가 **"이 지역에서 검색"** 을 누르게 했다.

### 2.5 마커가 잘렸을 때 숨기지 않는다

서버 한 페이지 상한이 100건이다. 반경 안에 그보다 많으면 일부만 보인다.
그대로 두면 **"이게 전부" 라고 오해**하므로 *"이 지역 N곳 중 M곳만 표시했습니다"* 를 띄운다.

시설 정보를 "모름" 으로 표시하는 것과 같은 원칙 — **불완전한 것을 감추지 않는다.**

## 3. ★ 실패 기록 — 원인이 네 겹이었다

지도가 **"빈 화면에 마커만 뜨는"** 상태였다. 증상 하나에 원인이 넷이었고,
그중 둘은 **증상이 완전히 같아서** 오판을 불렀다.

### 3.1 `CLIENT_ID` 가 아니라 `NCP_KEY_ID` 다

```
E/NaverMap: Authorization failed: [401] Unauthorized client
```

NCP 콘솔이 **"Client ID"** 라고 부르지만 신형 NCP 키라
`com.naver.maps.map.NCP_KEY_ID` 를 써야 했다. SDK 3.21 은 둘 다 지원한다.

**마커만 보이는 이유**: 마커는 오버레이라 SDK 가 로컬에서 그리고, **타일만 서버에서 받아온다.**
인증이 막히면 타일만 사라지고 마커는 그대로 남는다.

### 3.2 인증 실패가 화면에 표시되지 않았다

`OnAuthFailedListener` 를 등록하지 않으면 SDK 는 **조용히 실패한다.**
타일만 안 나오고 화면 어디에도 이유가 없어 Logcat 을 봐야만 알 수 있었다.

리스너를 등록해 오류 코드와 메시지를 화면에 띄우도록 고쳤다.
SDK 는 `UnauthorizedClientException` / `ClientUnspecifiedException` / `QuotaExceededException` 를 구분해 던진다.

### 3.3 지도 표면 생성 중 마커 100개를 올려 ANR

```
ANR in org.duckdns.woodysside.campingfinder
Reason: Input dispatching timed out (Application does not have a focused window)
34% CPU   ← 데드락이 아니라 계속 일하는 중
```

진입 즉시 자동 검색하도록 짰던 것이 원인이었다.
**지도가 먼저 뜨고, 사용자가 "이 지역에서 검색" 을 눌러야 마커가 올라오게** 바꿨다.

함께 고친 것: `forEach` 안에서 조건부로 `rememberMarkerState` 를 부르고 있었다.
재구성마다 `remember` 호출 구조가 달라져 슬롯이 어긋난다. **`key()` 로 감쌌다.**

### 3.4 ★ map-sdk 3.21.0 이 최신 지도 스타일을 파싱하지 못한다

인증을 고쳤는데도 **여전히 격자 배경에 마커만** 보였다. 로그가 달랐다.

```
W/NaverMap: [ParseStyle]: Unsupported layer type: mesh-batch
W/NaverMap: [ParseStyle]: invalid source type
```

네이버 서버가 내려주는 스타일에 SDK 가 모르는 레이어 타입이 있었다.
**스타일이 깨지면 그릴 레이어가 없어 배경이 격자만 남고, 오버레이인 마커만 보인다** — 3.1 과 증상이 같다.

| | 구분점 |
|---|---|
| 인증 실패 | 로그에 `[401] Unauthorized client` |
| 스타일 실패 | 로그에 `ParseStyle` |

`naver-map-compose 1.9.0` 이 끌고 오는 map-sdk 는 3.21.0 이다.
**래퍼가 가져오는 SDK 버전을 그대로 믿으면 안 된다** — 래퍼는 갱신이 느린데
**지도 스타일은 서버가 계속 바꾼다.** `map-sdk` 를 3.23.3 으로 명시해 덮어썼다.

### 3.5 에뮬레이터 그래픽이 무너져 앱 전체가 검은 화면

지도를 연 뒤 **앱 전체가 검게** 되어 아무것도 확인할 수 없었다. 앱 문제가 아니었다.

| 근거 | 내용 |
|---|---|
| 크래시 | 없음 |
| UI 계층(uiautomator) | 정상 — "2955곳", 캠핑장 이름·시설 전부 존재 |
| 실제 화면(screencap) | 15KB 단색 PNG (정상이면 100KB 이상) |
| AVD 설정 | `hw.gpu.mode=auto` · 로그에 `Vulkan 1.4 is not supported for the guest` |

**앱은 화면을 제대로 만들고 있는데 에뮬레이터가 그리지 못하는 상태**였다.

> **교훈: 지도는 에뮬레이터로 검증하지 않는다.**
> GL 렌더링이 무겁고 에뮬레이터마다 구현이 달라, 나는 문제가 앱 문제인지 구분되지 않는다.
> 실기기(Galaxy S25)에 연결하자 타일·마커가 한 번에 정상 동작했다.
