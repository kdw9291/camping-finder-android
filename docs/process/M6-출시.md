> 2026-08-11 · 진행 중
> 목표: 스토어 링크 하나로 증명되는 상태. 이 프로젝트가 다른 두 개와 다른 이유다.

---

## 0. 이 단계의 성격

M0~M3 은 "만들면 끝나는" 일이었다. M6 은 아니다.
**대기 시간이 작업 시간보다 길다.** 코드로 할 수 있는 일을 아무리 빨리 끝내도
비공개 테스트 14일은 줄일 수 없다. 그래서 순서가 곧 일정이다.

임계 경로는 하나다 — **테스터 12명 × 14일 연속.**
나머지 항목은 이 14일 안에 병렬로 끝낼 수 있다.

```
오늘 ─┬─ 개발자 계정 결제·심사 (1~2일) ─┬─ 비공개 테스트 트랙 생성 ─── 14일 대기 ───┬─ 프로덕션 심사 (1~7일) ─ 출시
      ├─ 테스터 모집 (며칠~1주) ────────┘                                          │
      ├─ 릴리스 빌드 검증 (R8) ──────────────────────────────┐                     │
      ├─ 아이콘·그래픽 ──────────────────────────────────────┤ 이 14일 안에 끝내면  │
      ├─ 개인정보처리방침 배포 ──────────────────────────────┤ 일정에 영향 없음     │
      └─ 스토어 등록정보·데이터 보안 ────────────────────────┴─────────────────────┘
```

**따라서 오늘 할 일은 코드가 아니라 계정 결제와 테스터 모집이다.**
나머지는 이미 준비해 뒀다(아래 2번).

## 2. 오늘 한 것 (2026-08-11)

### 2.1 위치 권한을 뺐다

`ACCESS_COARSE_LOCATION` 이 매니페스트에 선언돼 있었는데, **코드 어디에서도 쓰지 않고 있었다.**
기기 위치를 읽는 코드는 M5 에 있고, 현재 반경 검색은 지도 중심 좌표로만 동작한다.

쓰지 않는 권한을 선언한 채 올리면 데이터 보안 양식에 "위치 수집"을 신고해야 한다.
실제로 수집하지 않는데도 그렇다. 거짓으로 "수집 안 함"이라 답하면 정책 위반이고,
정직하게 답하면 스토어 페이지에 위치를 수집하는 앱으로 표시된다. 둘 다 손해다.

**권한은 업데이트로 언제든 추가할 수 있다. 빼는 것은 이미 신고한 데이터 보안 항목을
되돌리는 일이라 더 번거롭다.** 없는 상태로 시작하는 쪽이 되돌리기 쉽다.

주석으로 남겨 뒀으므로 M5 에서 주석만 풀면 된다.

### 2.2 R8 을 켰다

M3 까지 미뤄 둔 이유가 문서에 적혀 있었다 — "Retrofit·serialization keep 규칙을 검증하지 않고
켜면 디버그에선 되고 릴리스에서만 깨지는 조용한 실패가 된다."

규칙은 `app/proguard-rules.pro` 에 썼다. 가장 위험한 두 곳:

| 위험 | 증상 | 대응 |
|---|---|---|
| kotlinx.serialization | `SerializationException: Serializer for class 'X' is not found` | `@Serializable` 동반 객체 보존 + DTO 패키지 통째 keep |
| Retrofit 제네릭 | `IllegalArgumentException: Unable to create converter for ...` | `-keepattributes Signature` + API 인터페이스 keep |

네이버 지도는 아예 통째로 keep 했다. M3 에서 지도가 안 그려지는 실패를 이미 두 번 당했고,
그때 원인이 인증인지 스타일 파싱인지 판별하는 데 시간이 걸렸다.
**R8 을 원인 후보에서 제거하는 것이, 몇 KB 줄이는 것보다 싸다.**

DTO 를 통째로 keep 한 것도 같은 계산이다. DTO 는 20여 개뿐이고 필드명이 서버 응답과
1:1로 묶여 있어 난독화 이득이 사실상 없다.

> ⚠️ **빌드가 통과했다는 것은 아무 증거도 되지 않는다.** R8 실패는 컴파일이 아니라 런타임에 나온다.
> 반드시 릴리스 빌드를 실기기에 설치해 실제 API 호출까지 확인해야 한다.

### 2.3 아이콘을 벡터로 만들었다

`minSdk = 26` 이라 **적응형 아이콘만으로 전 기기를 덮는다.** PNG 폴백(mipmap-hdpi ~ xxxhdpi)이
필요 없다는 뜻이다. 밀도별 PNG 다섯 벌 대신 벡터 두 개(전경·모노크롬)로 끝냈다.

입구(삼각형 구멍)를 배경색 도형으로 덮지 않고 `fillType="evenOdd"` 로 뚫은 이유:
Android 13+ 테마 아이콘은 시스템이 배경을 사용자 배경화면 색으로 바꾼다.
배경색 도형으로 덮었다면 그 기기에서 입구만 옛 색으로 남는다.

### 2.4 ★ 실패 기록 — 권한을 뺐는데 빠지지 않았다

2.1 에서 `ACCESS_COARSE_LOCATION` 을 주석 처리했다. **그걸로 됐다고 생각한 것이 틀렸다.**

병합된 릴리스 매니페스트를 실제로 열어 보니 그대로 들어 있었다.

```
$ grep uses-permission app/build/intermediates/merged_manifest/release/.../AndroidManifest.xml
android.permission.ACCESS_COARSE_LOCATION   ← 선언한 적 없다
android.permission.ACCESS_NETWORK_STATE
android.permission.ACCESS_WIFI_STATE
android.permission.INTERNET
```

#### 어디서 들어왔나

```
io.github.fornewid:naver-map-compose:1.9.0
  └ io.github.fornewid:naver-map-location:21.0.1        ← 여기
      └ com.google.android.gms:play-services-location:21.0.1
```

앱 코드는 이 모듈의 API 를 **한 곳도** 참조하지 않는다 —
`LocationSource`·`LocationOverlay`·`FusedLocation` 전부 미사용이고,
반경 검색은 지도 중심 좌표로만 한다. **권한만 따라 들어왔다.**

#### 왜 심각한가

2.1 에 적은 이유가 통째로 무효였다. 이 상태로 제출했다면:

- 데이터 보안 양식에 위치를 신고하거나, 신고하지 않아 **정책 위반**이 된다
- 스토어 페이지에 위치 수집 앱으로 표시된다
- 그리고 **아무도 그 사실을 모른 채** 올라간다 — 소스에는 주석 처리돼 있으니까

#### 어떻게 알아챘나

4.3 매니페스트 확인 절차를 실제로 돌렸다. 이 문서 3번 함정 표에
*"AD_ID 권한 — 라이브러리가 몰래 병합했을 수 있다"* 라고 적어 둔 그 항목이다.
AD_ID 는 깨끗했고, **적어 두지 않은 쪽에서 났다.**

> 소스 매니페스트를 읽고 "이 권한은 없다" 고 말하면 안 된다.
> 앱이 선언하는 것은 **병합된** 매니페스트다.

#### 고친 방식

```xml
<uses-permission
    android:name="android.permission.ACCESS_COARSE_LOCATION"
    tools:node="remove" />
```

의존성에서 `naver-map-location` 을 `exclude` 하는 방법도 있지만 쓰지 않았다 —
래퍼 내부가 그 클래스를 참조하면 런타임에 `NoClassDefFoundError` 로 터지고,
그건 지도가 안 뜨는 증상으로만 보여 M3 에서 이미 시간을 태운 종류의 실패다.
권한만 걷어내는 쪽이 되돌리기 쉽고 실패가 조용하지 않다.

`ACCESS_NETWORK_STATE` 와 `ACCESS_WIFI_STATE` 는 남겼다. 둘 다 **normal 권한**이라
런타임 요청도, 데이터 보안 신고도, 스토어 표시도 없다. 지도 SDK 가 정당하게 쓴다.

### 2.5 개인정보처리방침을 API 서버에 얹지 않았다

`woodys-side.duckdns.org` 에 정적 페이지 하나 얹는 게 가장 쉬웠지만 그렇게 하지 않았다.

이 프로젝트의 EC2 는 **언제든 폐기·재생성할 수 있게** 만든 무상태 서버다(DEPLOY 문서 참고).
그런데 개인정보처리방침 URL 은 **앱이 게시된 동안 절대 죽으면 안 된다.** 링크가 죽으면
정책 위반으로 앱이 내려간다.

되돌릴 수 있게 만든 것과 절대 죽으면 안 되는 것을 같은 곳에 두면, 앞의 성질이 사라진다.
GitHub Pages 로 분리했다.

**앱 코드 저장소에도 얹지 않았다** — 같은 논리다. `camping-finder-android` 를
나중에 private 으로 바꾸거나 정리하면 Pages 가 함께 죽는다. 방침 URL 이 코드 저장소의
공개 여부에 종속될 이유가 없다. 전용 저장소를 따로 뒀다.

**배포 완료 (2026-08-11)**

```
https://kdw9291.github.io/camping-finder-io/privacy-policy.html
```

| | |
|---|---|
| 저장소 | [kdw9291/camping-finder-io](https://github.com/kdw9291/camping-finder-io) · public · `main`/`(root)` |
| 원본 | `docs/release/privacy-policy.html` (앱 저장소) |
| 게시본 | 위 저장소 루트 — 원본을 복사해 온 것 |

> ⚠️ 방침이 **두 곳에 존재**하게 됐다. 고칠 때는 원본 → 게시본 순서로 간다.
> 게시본을 직접 고치면 어느 쪽이 맞는지 알 수 없게 된다.
>
> ⚠️ 저장소 이름을 `<아이디>.github.io` 로 했다면 URL 이 짧고 푸시만으로 Pages 가 켜졌다.
> 프로젝트 저장소라 Settings 를 손으로 켜야 했고 경로에 저장소명이 붙는다.
> 기능 차이는 없다 — 다만 스토어에 제출한 뒤에는 바꾸기 번거로우니 지금 형태로 확정한다.

### 2.6 versionCode 를 git 커밋 수에서 만든다

`versionCode` 는 Play 가 **"더 새 빌드인가"를 판단하는 유일한 기준**인 정수다.
사용자에게 보이는 `versionName`("0.1.0")과는 완전히 별개이고,
**한 번 쓴 숫자는 영원히 재사용할 수 없으며 항상 커져야 한다.**

손으로 관리하면 올리는 것을 잊는다. 잊으면 빌드(약 2분)와 업로드를 마친 뒤에야
"버전 코드 N은 이미 사용되었습니다" 로 거부당하고 처음부터 다시 한다.
비공개 테스트 14일 동안 수정본을 여러 번 올리므로 반드시 한 번은 당한다.

```kotlin
versionCode = versionCodeFromGit   // git rev-list --count HEAD
```

**커밋 수를 고른 이유는 단조 증가가 아니라 추적 가능성이다.**
같은 커밋은 항상 같은 숫자가 나오므로, 테스터가 "앱이 이상하다" 고 할 때
versionCode 로 **정확한 커밋을 찾을 수 있다.**

| 방식 | 단조 증가 | 커밋 역추적 | 외부 의존 |
|---|---|---|---|
| **git 커밋 수** (채택) | 대체로 | **가능** | git |
| 타임스탬프 | 항상 | 불가능 — 같은 커밋도 빌드마다 다름 | 없음 |
| 수동 | 사람이 기억하는 만큼 | 가능 | 사람 |

첫 적용 결과 `versionCode = 10`. 아직 아무것도 업로드하지 않았으므로
1 을 건너뛰고 10 부터 시작해도 문제가 없다 — **커지기만 하면 된다.**

#### 손으로 지정하는 법

```powershell
.\gradlew.bat bundleRelease -PversionCode=42
```

git 히스토리를 squash·rebase 해서 커밋 수가 **줄어든 경우**, git 이 없는 환경,
CI 빌드 번호를 쓰고 싶은 경우에 쓴다. 자동값을 그냥 덮어쓴다.

되돌리려면 `app/build.gradle.kts` 의 `versionCode = versionCodeFromGit` 을
숫자 리터럴로 바꾸면 된다. 그때는 업로드마다 손으로 올려야 한다.

#### 실패는 조용하지 않게 했다

git 을 못 찾으면 **빌드를 세운다.** 1 같은 값으로 조용히 떨어뜨리지 않는다 —
이미 쓴 것보다 작은 versionCode 가 나가면 업로드 단계에서야 알게 되고,
그때는 "왜 거부되는지" 를 한참 찾는다. 설정 단계에서 시끄럽게 죽는 편이 싸다.

```
versionCode 를 만들 수 없다 - git 저장소가 아니거나 git 을 찾지 못했다.
  수동으로 지정: ./gradlew <task> -PversionCode=<정수>
```

`providers.exec` 를 쓴 것도 이유가 있다. 설정 단계에서 `ProcessBuilder` 를 직접 돌리면
구성 캐시(configuration cache)를 켜는 순간 깨진다. Gradle 이 매 빌드마다 켜라고 권하고 있어
언젠가 켤 텐데, 그때 원인을 찾기 어려운 자리다.

## 3. 함정 (M6 에서 당하기 전에 적어 둔 것)

| 함정 | 내용 |
|---|---|
| **업로드 키 분실** | 이 프로젝트에서 가장 되돌릴 수 없는 항목. 잃으면 같은 앱으로 업데이트 불가 → 패키지명 바꿔 새 앱. `.jks` 와 비밀번호를 **서로 다른 곳**에 백업 |
| **NCP 지문** | Play 앱 서명을 쓰면 사용자가 받는 APK 는 **Google 키로 재서명**된다. NCP 에 업로드 키 지문만 등록하면 스토어에서 받은 앱에서 지도가 안 뜬다. Play Console → 앱 서명 의 **앱 서명 키 SHA-1** 도 등록할 것 |
| **패키지명** | `org.duckdns.woodysside.campingfinder` — 업로드 후 영원히 변경 불가 |
| **테스터 카운트** | 14일 **연속**. 중간에 12명 아래로 떨어지면 끊긴다. 여유 있게 15~18명 |
| **테스터 계정** | Google 계정(gmail) 이어야 한다. 카카오 계정 아님 |
| **R8 런타임 실패** | 빌드 성공은 증거가 아니다. 실기기 검증 필수 |
| **AD_ID 권한** | 라이브러리가 몰래 병합했을 수 있다. 병합된 매니페스트로 확인할 것 (확인함: 깨끗하다) |
| **위치 권한 재병합** | ★ **실제로 당했다.** 주석 처리해도 `naver-map-location` 이 다시 넣는다. `tools:node="remove"` 로 걷어냈다. 2.4 참고 |
| **방침 URL 생존** | 죽으면 앱이 내려간다. API 서버·코드 저장소와 분리했다. **`camping-finder-io` 를 지우거나 private 으로 바꾸지 마라** — 무료 플랜에서 private 은 Pages 가 안 돈다 |
| **targetSdk** | 현재 37. Play 의 신규 앱 요구 수준을 넘는지 제출 직전 재확인 |
| **versionCode 감소** | git 커밋 수에서 만든다(2.6). 히스토리를 squash·rebase 하면 **숫자가 줄어** 업로드가 거부된다. 그때는 `-PversionCode=N` 으로 넘긴다 |

## 5. 릴리스 체크리스트

**빌드를 스토어에 올릴 때마다 이 순서로 한다.** 순서에 이유가 있는 자리를 ★ 로 표시했다.

두 저장소 모두 `main`(스토어에 올라간 것) + `dev`(작업용) 구조다.
`main` 은 자동으로 따라오지 않는다 — 실제로 API 저장소가 7커밋 뒤처져
저장소를 열면 빈 것처럼 보이는 상태로 한동안 방치됐다.
**`main` 을 갱신하는 시점을 "릴리스할 때" 로 못 박아 그 표류를 막는다.**

### 5.1 코드 확정

- [ ] `dev` 에서 작업이 끝났고 테스트가 통과한다

```powershell
.\gradlew.bat testDebugUnitTest connectedDebugAndroidTest
```

- [ ] ★ `main` 으로 병합한다. **릴리스는 `dev` 가 아니라 `main` 에서 빌드한다**

```powershell
git checkout main; git merge --ff-only dev
```

`--ff-only` 를 쓴다. 병합 커밋이 끼면 커밋 수가 늘어 `versionCode` 가
`dev` 에서 세던 것과 어긋난다(2.6). 어긋나도 커지기만 하면 동작은 하지만,
"이 빌드가 어느 커밋인가" 를 역추적할 때 한 단계가 더 생긴다.

- [ ] 태그를 붙인다. **`versionCode` 를 이름에 넣는다**

```powershell
$vc = git rev-list --count HEAD
git tag "v0.1.0-vc$vc"
git push origin main --tags
```

테스터가 "앱이 이상하다" 며 알려주는 것은 대개 `versionCode` 뿐이다.
태그에 그 숫자가 있으면 커밋을 바로 찾는다.

### 5.2 빌드

- [ ] AAB 를 만든다 (`versionCode` 는 자동 — 2.6)

```powershell
.\gradlew.bat bundleRelease
```

- [ ] ★ 실기기 검증용 APK 도 같이 만든다. **AAB 는 기기에 설치할 수 없다**

```powershell
.\gradlew.bat assembleRelease
adb install -r app\build\outputs\apk\release\app-release.apk
```

- [ ] 4.2 실기기 체크리스트를 통과한다 (**에뮬레이터 금지**)
- [ ] 4.3 병합 매니페스트를 확인한다 (`--rerun-tasks` 필수)

### 5.3 업로드와 ★ 지문의 순서

- [ ] Play Console 비공개 테스트 트랙에 AAB 업로드
- [ ] ★ **업로드 직후, 테스터에게 링크를 뿌리기 전에** NCP 콘솔에 지문을 등록한다

여기가 이 문서에서 가장 틀리기 쉬운 자리다. NCP 에 등록할 지문이 **둘**이다.

| 지문 | 언제 얻나 | 이게 없으면 |
|---|---|---|
| **업로드 키** SHA-1 | 키를 만든 직후 | 내가 설치한 릴리스 APK 에서 지도가 안 뜬다 |
| **Play 앱 서명 키** SHA-1 | ★ **첫 AAB 업로드 후에야** Play Console 에 나타난다 | **스토어에서 받은 앱에서만** 지도가 안 뜬다 |

```
Play Console → 설정 → 앱 서명 → 앱 서명 키 인증서 → SHA-1
```

Play 는 업로드한 AAB 를 **Google 의 키로 다시 서명**해 배포한다.
그래서 내 기기에서는 멀쩡한 지도가 테스터 기기에서만 안 뜬다.
**14일 카운트가 이미 시작된 뒤에 발견하면 뼈아프다.**

- [ ] 스토어에서 받은 앱으로 지도를 다시 확인한다 (내가 설치한 APK 말고)

### 5.4 배포

- [ ] 테스터에게 참여 링크 배포
- [ ] 옵트인 인원이 12명을 넘는지 확인
      ([테스터 명단](../release/store-listing.md#6-비공개-테스트--테스터-모집) — 여유 있게 15~18명)

- [ ] `versionName` 을 올릴지 판단한다. **자동이 아니다** —
      무엇이 바뀌었는지는 사람이 정하는 것이지 커밋 수가 정할 일이 아니다 (2.6)
